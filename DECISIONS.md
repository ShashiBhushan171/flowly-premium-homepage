# Design Decisions — Flowly

## 1. Why did I choose this approach?

I chose a static HTML and CSS approach for the Flowly homepage because the project is primarily focused on visual design, responsive layout, and presenting the product clearly.
The homepage uses HTML for the page structure and CSS for the layout, typography, spacing, responsive behavior, and visual effects. I kept the implementation simple instead of using a frontend framework because a framework was not necessary for this single-page marketing website.
The main goal was to create a clean and premium-looking homepage that communicates Flowly's workflow automation concept quickly.

## 2. One trade-off I made

Because of the time limit, I focused on the visual presentation and responsive layout instead of building a fully functional workflow automation system.
The workflow shown on the homepage is a visual representation of how Flowly could work:

Trigger → Action → Result

With more development time, I would add a more interactive workflow demonstration, improve accessibility testing, and test the page across more browsers and devices.

## 3. Where did I use AI tools?

I used AI tools during development to help brainstorm the page structure, generate and improve some HTML/CSS ideas, and troubleshoot layout and responsive-design issues.
After receiving suggestions, I personally reviewed the code and tested the website in the browser. I adjusted the spacing, typography, card layout, responsive behavior, navigation, and other styling based on the actual result.
I also verified the homepage at mobile and desktop widths and made changes when the generated code did not produce the intended result.
The final implementation was reviewed and tested by me rather than being submitted without verification.
